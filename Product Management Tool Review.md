## Product Management Tool Review

\## Gabriel Mendenhall (without AI, thanks for asking :)

\### **Jira**

* The **main draw** for [Jira](https://www.atlassian.com/software/jira) is the view of tasks, displayed on a Timeline, Kanban Board, or in a list format. Each task has people assigned to it, and whether or not it was completed yet. The **Kanban Board workflow** generally has tabs for 'To Do, In Design, In Development, GTM Launch, and Done.' From what I understand, there is modular blocks for the tabs on the board, and you can switch them in and out. Additionally, it seems that tasks have hyperlinks for the project or software being used, such as a GitHub link, a canva invite, etc. When it comes to **tracking progress**, each task has a specific id that is attached to a person who created it. There is lots of customization for **blockers, notes, etc** with features in the ticket itself. You can click on the link, and add a descriptive note, then connect that ticket to the uproot issue or a related problem. Considering our heavy focus on Agentic deployment, something **useful for the Capstone class** would definitely be the in-site agentic deployment. You can add an Agent to a task and it will begin to outline and then work on it on it's own. Something that is a little contrived and **tangential** to what an MVP would supply is certainly the asynchronous videos and AI notes. Both of these, powered by agents, are used for conferences and meetings. Considering most meetings will be in a small group, this doesn't have enough realized advantage to be a real asset to an MVP Management Tool.





\### GitHub Projects

* Clearly the **main draw** for [GitHub Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/creating-projects/creating-a-project) would have to be the modularity of the tasks, and the integration of it all within your own GitHub Repos. Like Jira, you can pick from a Timeline, a Roadmap, or a Board (although you are committed to just that one, unlike in Jira). Projects are **represented** with an ID attached to a GitHub Repo, and they can start as issues, pull requests, or more. They can be added in bulk, which implies a robust interface that can quickly make similar Projects. \*\*Blockers and Notes\*\* appear in the Relationships section, where you can see whether each Issue is a Block, a Note, or a Bottleneck that needs to be completed to move on with the project. This seems especially \*\*useful for the Capstone class\*\*, as being able to visually see what bottlenecks everything and then discussing it as a team is the key to working more efficiently. Additionally the integration with GitHub and the fact that it's almost entirely free makes it an easy entry point, which is something college students love (believe me, I know from experience). Two parts of GitHub Projects that \*\*aren't necessary for an MVP\*\* would include the idea of having multiple teams, the different table styles, and the Sub-issues table. In the scope of projects we'll be doing, I think we'll never need to be detailing sub-problems within issues and problems themselves. There isn't that many moving parts. 





\### MVP Implications

* A Kanban board-like display
* Organizational Tabs ranging from Backburner to Complete
* Assign a task for each person
* Rate the priority from Low to High
* High level Integration with links to projects
* Notes on tasks, which will include Blockers by extension



\### Excluded Capabilities

* Rich Agentic integration
* Multiple views of boards
* Alerts/Notifications
* Capacity Checks to tell individuals if they have too many tasks
